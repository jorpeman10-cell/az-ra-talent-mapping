# 用工决策引擎改造方案：三层风险结构（替代单一 CV 点值折减）

> 版本 v1.0 · 2026-09-05 · Kimi
> 依据：`prd_analysis/results.md`（2026-09-05 实证三章：CV 稳定性 / 强相关扫描 / 波动可预测性）
> 范围：`headhunt-service/pipeline/`（engine.py、run.py、collect/cleaning）、`api/`（main.py、rationale.py）、`config/config.yaml`
> 红线：模型只输出建议，PIP/晋升/淘汰决策必须人工签署（不变）

## 1. 为什么改（实证依据）

| 发现 | 出处 | 对现状的含义 |
|---|---|---|
| 同一顾问前后半段 CV 相关 ρ=0.03（p=0.90） | results.md §1 | CV 不是稳定特质，裸 CV 点值折减无支撑 |
| 理论 CV 公式高估约 5 倍（口径错配：p 实证 ≈0.6% vs PRD 33.3%） | §2 | v6.2 的理论 CV 先验不可用 |
| 波动部分可预测：M ρ=−0.52、活动量均值 ρ=−0.61、活动量波动 ρ=+0.57 | §7.1 | CV 有结构性先验可用（收缩有了锚） |
| Δ活跃客户数（t−1）→ 下季滚动 CV 上行，ρ=−0.29（q<0.001） | §7.2 | 唯一显著预警因子，做监测触发器 |
| 签约额/单数/客单价 → 下季回款 ρ=0.40–0.58 | §6 | 产能基数维持管道口径（max(μ×4, 签约×回款率)），已实证 |

## 2. 目标结构（三层）

### L1 — CV 降级为区间输入（先验收缩）

现：`calculate_effective_capacity()` 用裸 CV（min(回款CV, 面试CV)）直接进折减。
改：

```
CV_prior = a − b1·ln(M) + b2·活动量CV          # 由横截面回归标定（首期系数来自 §7.1 数据，参数进 config）
CV_shrunk = [k/(n+k)]·CV_prior + [n/(n+k)]·CV实际   # n=有效季度数，k=8（沿用 v6.2 贝叶斯混合骨架）
```

- n=0（新人通道）→ 纯先验；n≥8 → 以实际为主
- 先验系数 a/b1/b2 写入 `config.yaml`（`risk.cv_prior: {a, b1, b2, k}`），季度可重标定
- `capacity` 输出新增 `cv_prior` / `cv_shrunk` 字段（原 `cv_used` 保留）

### L2 — 监测触发器（Δ活跃客户数）

新增季度序列：每顾问每季活跃客户数（C 表按 client_id 去重计当季有签约动作的客户）。
规则：

```
客户流失预警 = 连续 2 季 Δ活跃客户数 < 0
触发 → 当季折减率 +5pp（可配置 risk.churn_addon_pp，默认 5），并在 rationale 明示
```

- 只做加法、只监测不折算（忠实于实证：它是预警信号不是 CV 替代品）
- 输出进 `capacity.monitoring`: {`client_delta_2q`, `churn_alert`: bool}

### L3 — 分位情景压测替代点值

现：单一 conservative 产能 → 单一 NPV/利润率点值。
改：收缩后 CV 分布上取三档产能分位，与现有市场情景 A/B/C 正交：

```
产能分位（CV_shrunk 驱动）：P25 乐观 / P50 基准 / P75 悲观
每档输出 NPV / IRR / 首年利润率 / 雇佣极限月薪
```

- `salary_scan` 的 points 增加 `quantile` 维度（每档情景×分位一组点）
- 决策表述从"建议 X"改为"基准档 X、悲观档 Y"，rationale 同步

## 4. 黄金样本回归怎么跟

1. **冻结基线**：改造前先给当前引擎跑一次 `tests/test_golden.py --update` 之外的全量历史快照（board + 12 顾问全字段），存 `tests/golden_v1_baseline.json`——作为"改造前行为"的永久对照
2. **新黄金**：改造后 `test_golden.py --update` 重新生成 `golden_board.json`；diff 报告必须人工过目（哪些顾问决策变了、为什么）
3. **新增用例**：
   - 新人通道（无回款有管道）在三层结构下的输出形态
   - CV 收缩单调性：n=0 时 CV_shrunk==CV_prior；n→∞ 时趋近 CV实际
   - L2 触发器：构造连续 2 季客户流失的合成顾问，断言折减 +5pp 且 rationale 含预警
   - L3 分位：P25 ≥ P50 ≥ P75 单调；默认参数下基准档与 v1 点值差异 <2pp（兼容性锚）
4. **容差纪律**：数值容差维持 0.01；分位/监测新字段进 golden 比对范围
5. **回测验收**：留出 4 季度回测重跑（tune_backtest 同款），三层 vs 现版比 MAPE——不改善不上线（现基线 MAPE 69.5%）

## 5. 上线顺序（遵守"完整验证后单一推送"）

## 附：实施校准记录（2026-09-05 完工）

**L1 先验系数（实证标定，prd_analysis/results.md §8）**：`CV_prior = 1.6716 − 0.4454·ln(M) + 0.3667·推荐季CV`（n=24，LOOCV R²=0.32），clip [0.1, 2.5]。

**实施中对原方案的 4 处修正**：
1. **单侧收缩**：先验只压制高噪音端（actual > prior 才混合），实测低 CV（min 口径精选值）不上拉——双向混合曾把于肖肖从 EMPLOY 误判 INCUBATE（cv 0.324→0.94），单侧后生产数值逐位一致
2. **新人 M 估计下限 1.0**：先验回归训练范围 M∈[3,24]，签约额÷客单价中位数的估计值不再外推到 1 以下
3. **L2 只看已完结季度**：当季未完结的客户数必然偏低，会造成假性流失预警
4. **活动 CV 窗口从入职季度起算**：入职前季度不计零（否则新人 rec_cv 被预入职零值高估约 3 倍）

**回测结果（backtest_threelayer.py，as_of=2025Q3 前瞻 3 季）**：legacy MAPE 68.31% → 三层 67.37%（−0.94pp），13 名顾问仅 1 名行为不同（863：30.0 vs 31.9，三层更接近实际 15.9）。决策零回归（12 人 board 与生产逐位一致）。差异小是设计使然——单侧收缩只作用于高噪音个案。

**契约决策**：capacity 新增的 quantiles/monitoring/cv_prior 结构化字段 v1 不进聊天卡白名单（Lobe strict schema 不动，规避一轮契约变更）；三档与预警信息由 rationale 文本和 HTML 报告承载。后续如需结构化展示，按契约文档清单单独起一批。
