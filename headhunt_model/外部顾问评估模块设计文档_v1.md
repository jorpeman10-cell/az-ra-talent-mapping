| # | 决策 |

## 二、整体架构与数据流

```
┌─ headhunt_model 本地代码（引擎源头）────────────────────────────┐
│  step6_questionnaire.py    问卷定义模型 + 默认模板 + 版本管理       │
│  step7_candidate.py        外部候选人规则引擎（定级/定薪/条线）     │
└──────────────┬──────────────────────────────────────────┘
               ↓ 服务化封装（headhunt-svc FastAPI）
┌─ headhunt-svc（ECS 18801）───────────────────────────────────┐
│  POST /candidate/intake          HR 录入候选人 → 建档 + 自评链接   │
│  GET  /q/{token}                 候选人自评页（公开 token）        │
│  POST /q/{token}/submit          自评提交入库                     │
│  POST /candidate/{id}/hr-assess  HR 面评录入/存档                 │
│  POST /candidate/{id}/assess     规则引擎：定级+定薪+盈亏平衡线     │
│  GET/PUT /questionnaire/template 问卷模板查看/编辑（HR 后台）      │
│  存档: /data/candidates/{id}/   档案+两份问卷+评估结果 JSON        │
└──────────────┬──────────────────────────────────────────┘
               ↓ 意图网关新增 pack（同现有 headhunt.* 模式）
┌─ LobeHub 对话侧 ────────────────────────────────────────────┐
│  4 个 CANDIDATE pack（见第五节）+ 结果卡                        │
│  AI 叙事报告 → report_builder → hiijob.cn/intelligence/report/ │
└──────────────────────────────────────────────────────┘
```

**核心数据流**：HR intake 建档 → 发自评链接（48h）→ 候选人提交（SELF_DONE）→ HR 面评（HR_DONE）→ 触发 assess → 规则结果 + AI 叙事 → HR 签署 decision.json 归档。

**关键边界**：所有钱的数字出自确定性规则引擎；AI 只消费结构化结果做叙事，无改级别入口。

## 三、问卷设计（默认模板 + 编辑器）

### 3.1 模板结构

JSON、版本化；每份答卷绑定模板版本号存档，HR 改题不影响历史档案。

```json
{
  "template_id": "consultant_v1",
  "version": 3,
  "dimensions": [
    {"id": "performance", "name": "业绩证据", "weight": 0.35, "questions": [...]}
  ]
}
```

### 3.2 五维度默认模板（自评卷/面评卷同维度、不同问法）

| 维度 | 权重 | 自评卷问法示例 | 面评卷问法示例 | 引擎作用 |
|------|------|--------------|--------------|---------|
| 业绩证据 | 35% | 近三年每年个人回款？最大单笔成单金额和客户？（数字+描述） | 声明业绩有无可验证证据（流水/邮件/offer 截图）？夸大痕迹打分 | 主映射职级：申报回款×验证系数 → 对齐职级目标线 |
| 领域深耕 | 20% | 主攻哪些治疗领域/职能？各领域成单占比？ | 领域知识提问打分（靶点/管线/组织架构层级） | 条线归属：与现有条线计算重合度 |
| 三速差 | 20% | 最近一次从接到 JC 到推荐首推的过程和耗时 | 情景题：真实 JC 现场说寻访路径，评速度/情报/人脉 | 定级修正 + 匹配度叙事素材 |
| 稳定性 | 15% | 过往换平台原因？当前看机会原因？ | 离职原因交叉验证、背调风险打分 | 定级修正（-1 级~0）+ 叙事风险 |
| 协作与合规 | 10% | 与 RD/其他顾问分单处理方式举例 | 合规红线情景题（飞单/私收简历/挖同事客户） | 一票否决 + 叙事 |

题型：单选（带分值）、数字填空（业绩）、多选（领域标签）、开放描述（证据，供 AI 叙事引用）。

### 3.3 两个关键机制

1. **验证系数**：自评申报回款 × 面评验证系数（0.5~1.0）= 有效申报业绩。同维度自评/面评分差 > 1 档 → 该维度 DIVERGENT 标记。
2. **合规一票否决**：合规维度任一题触发红线 → 输出 `REJECT_REVIEW`（建议不录用，人工复核），不进定级流程。

### 3.4 HR 编辑器

`/questionnaire/template` 管理页：增删维度、改权重（强制合计 100%）、改题目选项分值、发布新版本（版本自增）。编辑器只改模板，不碰历史存档。

## 四、评估引擎（step7_candidate.py，纯确定性）

### 4.1 定级

```
有效申报业绩 = 自评申报年回款(近2年均值) × 验证系数(面评业绩维度 0.5~1.0)
基准职级     = GRADE_TARGETS 表（ACT 30万→…→ECON 120万，policy_clauses 配置化）
修正项（可叠加，下不越 ACT，上不越 ECON）:
  稳定性 < 3 档                 → 降 1 级
  三速差 < 3 档                  → 降 1 级
  领域深耕 ≥ 4 档且重合线 ≥ 60%  → 升 0.5 级（四舍五入）
合规红线触发                    → REJECT_REVIEW，不定级
输出: 建议职级 + 逐条 rationale（格式沿用现有引擎）
```

### 4.2 定薪

```
内部带宽  = 同职级内部顾问底薪分布 P25/P50/P75（salary_loader 数据）
市场锚点  = HR 季度维护的分级市场底薪锚点表（一期手录，二期分位库替换）
薪资带宽  = 内部与锚点 6:4 加权混合；置信度：混合锚点或同职级内部样本≥2 → MEDIUM（封顶），
            纯内部小样本/借邻插值 → LOW
盈亏平衡线 = 复用财务引擎，按制度公式 现金薪酬 = max(底薪, 税后回款×tier)，
            含社保实算 + 公摊 6.37万/人/年，输出:
            - 带宽各档月薪对应的盈亏平衡年回款
            - 按职级目标线跑的 3 年 NPV 是否 ≥0
所有输出带置信度标签；无内部历史的候选人最高 MEDIUM
```

### 4.3 条线归属

候选人「领域深耕」多选标签 × 各条线权重向量 → 每条线重合度%；输出排序 + 首选条线 + 标签明细（给 AI 叙事用）。

### 4.4 偏差标记

五维度逐一比对自评/面评；分差 > 1 档 → DIVERGENT；≥3 维度 DIVERGENT → HIGH_DIVERGENCE 警示 + 验证系数额外 ×0.9。

### 4.5 错误处理

- 问卷不齐禁止 assess（状态机拦截）
- 某职级无内部样本 → 借相邻职级带宽插值 + LOW 标签
- 数字题离谱值（如回款 5000 万）→ 3σ 规则拒绝，提示 HR 复核

## 五、AI 叙事层 + 意图网关

### 5.1 新增 Capability Packs

| pack | 触发说法 | 确认级别 | 动作 |
|------|---------|---------|------|
| CANDIDATE_INTAKE | 「新增候选人 X / X 候选人建档」 | natural_language | 建档 + 返回自评链接 + HR 面评链接 |
| CANDIDATE_ASSESS | 「X 的定级定薪/薪资带宽/该定什么级」 | natural_language | 调 /assess，出结果卡 |
| CANDIDATE_NARRATIVE | 「X 的匹配度分析/评估报告」 | natural_language | 取档案+问卷原文，供 AI 叙事 |

> 勘误（2026-09-06，P2a 实施时定）：原设计的 CANDIDATE_HR_ASSESS 对话包取消——网关签名确认是单轮固定 slots 的零 LLM 机制，11 道结构化面评题无法可靠经对话收集。HR 面评改为表单页 `/h/{hr_token}`（7 天有效，intake 卡片同时返回），行为等价、可靠性更高。

> 注：模板读写实际路径为 `GET/PUT /api/template`（编辑页 `/template`），非 `/questionnaire/template`；P2 网关按此对接。

状态机：`CREATED → SELF_DONE → HR_DONE → ASSESSED → REPORTED`，缺环时对话告知 HR 下一步。

### 5.2 AI 叙事边界（护栏）

- 输入 = /assess 结构化 JSON（职级、带宽、条线得分、偏差标记、rationale、开放题原文）
- AI 只做：解读偏差（DIVERGENT 维度自评/面评原文对照）、匹配度叙事、风险提示
- AI 输出不得出现引擎 JSON 之外的数字；职级带宽原文引用
- 报告带固定免责声明：决策参考非自动决策、置信度标签、HR 签署才是录用决定
- 发布走 report_builder → `hiijob.cn/intelligence/report/{slug}`

## 六、存档与权限

```
headhunt-svc /data/candidates/{id}/
  profile.json            基本信息 + 简历摘要 + 目标条线
  self_assess.json        自评答案（绑定模板版本号）
  hr_assess.json          面评答案（绑定模板版本号 + 面试官）
  assessment_{ts}.json    每次评估全量留痕（多版本可对比）
  decision.json           HR 最终签署（录用/职级/底薪/签署人/时间）
```

- 自评链接：公开 token、48h 有效、提交即失效、单次提交（仿 blueprint_review）
- 权限：沿用 headhunt.* allowlist（当前 Steven），投产后加 HR 角色
- 合规：内部员工薪酬明细不进候选人模块，带宽只用分位数聚合（对齐 HR工具开发文档 §7-2）
